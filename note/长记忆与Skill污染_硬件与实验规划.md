# 长期运行 Agent 持久状态安全演化：硬件条件与实验规划

调研日期：2026-10-14。

## 1. 研究对象

建议把研究方向明确为：

> **长期运行 Agent 的持久状态安全演化、能力保留与可恢复性。**

第一阶段以规则和 Skill 为主要研究对象，同时保留向记忆格式、harness／policy、模型升级和工具状态迁移扩展的空间。规则和 Skill 是进入实验的切入口，状态转换和证据连续性是贯穿各阶段的研究中心。

研究对象包括：

- 长上下文中的系统规则、任务约束与用户偏好；
- 跨轮次和跨会话的长期记忆；
- 从经验生成的规则和 Skill；
- Skill 的加载、组合、版本更新与委托；
- 上下文压缩、摘要、重排和恢复；
- 污染发生后的隔离、降级、修复和退役。

重点研究以下变化：

```text
外部证据 → 当前上下文 → 摘要 / 记忆 → 经验规则
         → Skill / harness → 计划 → 工具调用
         → 外部状态 → 执行轨迹与证据 → 修订 / 迁移
```

每个状态对象都需要携带内容、来源、动作权威、适用范围、生命周期、父依赖、转换操作、验证证据和不确定性。研究重点是这些属性经过压缩、摘要、检索、合并、Skill 化、组合、模型升级、工具升级和执行后是否仍然成立。攻击者也可能通过工具返回、Skill 文件、历史记录、记忆检索或上下文压缩影响后续行为。

## 2. 安全目标

### 2.1 规则保留

长会话经过多轮对话、摘要和上下文压缩后，系统规则和任务边界仍然有效，并且仍然能够约束真实工具动作。模型、检索器、工具或记忆格式发生变化后，这些约束仍需要具备可验证的迁移条件。

可测量为：

```text
Rule Retention =
  经过语义等价检查且仍能约束动作的规则数 / 原始关键规则数
```

规则需要覆盖：

- 可调用工具；
- 可读写资源；
- 禁止的数据出口；
- 人工审批条件；
- 任务截止时间；
- Skill 的适用范围。

安全约束需要进行精确保留。压缩器无法证明语义等价时，保留原始约束的受保护副本，并限制不确定摘要驱动高影响动作。

### 2.2 污染抑制

不可信内容进入上下文或记忆后，必须经过来源、权限、适用范围和工具效果验证，才能改变后续计划和工具行为。

需要区分：

- 当前轮次影响；
- 跨轮次影响；
- 跨会话记忆影响；
- Skill 化后的持续影响；
- 对工具动作和外部副作用的影响。

### 2.3 能力保留

防御系统可能会拒绝部分内容或 Skill。研究需要回答：发现风险后，Agent 还能保留多少合法工作能力，并且这些能力能否迁移到参数变化、工具版本变化和留出任务。

定义安全能力曲线：

```text
Safe Utility(q) =
  污染或隔离条件 q 下完成合法任务的比例
```

能力保留需要同时报告原任务、参数变化任务、工具变化任务、模型迁移任务和留出任务，并记录过拒答率与能力侵蚀。安全系统可以隔离高风险能力，同时保留低风险的读取、分析和本地修改能力。

### 2.4 可恢复性

污染、来源变化、模型升级或工具升级被发现后，系统需要找到受影响状态及其后代，限制继续传播，并恢复到可继续工作的状态。

重点指标：

- 受影响状态定位召回率；
- 误伤的合法记忆比例；
- 残余污染率；
- 安全操作误阻断率；
- 计划前提与当前状态不一致率；
- 证据链覆盖率；
- 验证器信号冲突率；
- 撤销或过期后的信号失效延迟；
- 恢复后的任务完成率；
- 修复后连续任务完成率；
- 新一轮经验写入后的复发率；
- 模型或记忆格式迁移后的能力保持率；
- 恢复延迟；
- 重新读取、局部修复、重建和退役的成本。

## 3. 现有工作提供的实验基础

当前已经有八类可直接利用的基准：

1. **Skill 安全。** SkillSafetyBench 评测 Skill 面的安全失败，SkillsBench 评测 Skill 在多个任务和领域中的能力收益。两者可以共同测量“防御是否损害 Skill 的正常价值”。[R1–R2]
2. **Agent 工具安全。** AgentDojo 提供工具交互、间接提示注入和任务完成环境。[R3]
3. **记忆生命周期。** MemSecBench 关注记忆从持久化、后果产生到修复的完整过程；Mem2ActBench 关注记忆如何影响后续动作。[R4–R5]
4. **长上下文压缩。** The Compaction Cliff 提供按知识类型观察压缩、分解和检索失效的基线；StateComp 提供按 Agent 状态决定压缩时机和强度的基线。[R13–R14]
5. **Skill 泛化与攻击。** GSO 提供训练任务到留出任务的泛化测试；EvoSkill Injection 覆盖 Skill 创建、存储、检索和激活的攻击入口。[R15–R16]
6. **自演化安全效用。** Experience-Driven Self-Evolving Agents 提供执行经验、拒答经验、过拒答和正常效用的联合评估。[R17]
7. **状态修订与记忆操作。** STALE 关注跨轮次事实冲突和时间新鲜度；Supersede 训练记忆更新；MemStrata 用双时间账本处理事实失效；Text2Mem 将记忆操作写成可执行 schema；MemGuard 将验证器信号作为贯穿写入、检索、冲突处理、摘要和归档的持久元数据。[R20–R24、R31]
8. **行动谱系、Skill 审计与能力侵蚀。** PlanFence 绑定计划与动作相关依赖；AgentTrace 提供结构化运行轨迹；Counterfactual Trace Auditing 评估 Skill 对行为的改变；TRACE 将用户纠正编译为运行时规则；“Stale Does Not Mean Unsafe”区分失效竞态和无害竞态；CPE 和 REMM 分别覆盖能力侵蚀与可修订任务状态。[R23、R25–R30]

已有安全方法也应作为基线：

- 直接长上下文；
- 滑动窗口和摘要；
- RAG 长期记忆；
- worker/context 隔离；
- 来源和能力约束；
- Skill 静态检查；
- Skill 运行时检查；
- 记忆写入前验证；
- 污染后局部修复。

这些方法应当组成可替换的研究底座。文档中不把某一种压缩器、审查器或 Skill 扫描器固定为主方法，优先保留状态表示、证据记录、反事实重放和真实工具效果接口。

近期公开工作已经开始提出来源绑定与机器可检验的长期记忆授权保证。首项机制实验可以先固定模型和工具，完整记录状态转换与证据；跨模型、跨攻击路径和完整生命周期评测作为后续外部有效性扩展，逐步避免只测单一记忆写入场景。[R6]

## 4. 硬件条件分级

### 4.1 探索级单卡研究原型

适合完成规则丢失、长上下文污染、Skill 检查和记忆修复的主要实验。

建议配置：

- 单张 16–48 GB GPU，或云端／API 模型与本地受控工具组合；
- 16–32 核 CPU；
- 64–128 GB 内存；
- 1–2 TB NVMe；
- 本地 3B–14B 模型，4-bit 或 8-bit；
- 8K–64K 上下文长度；
- 可运行 vLLM、SGLang 或 Hugging Face 推理后端。

这一档足够完成：

- 4–32 轮长会话；
- 多个 Skill 的加载与组合；
- 记忆库和依赖图；
- 3–10 个并发 Agent；
- 污染、压缩、恢复和重放；
- 大规模参数扫描。

这一级硬件适合发现现象、校验状态表示、比较压缩和恢复策略。模型规模、上下文长度和工具复杂度只作为变量，不作为启动研究的前置门槛。首轮不把多机多卡或 TEE 设为必要条件。

### 4.2 机制验证级长上下文与多 Agent

适合研究 32K–128K 上下文、较大模型、多 Agent 协作和跨会话状态。

建议配置：

- 单张 48–80 GB GPU，或两张 24–48 GB GPU；
- 128–256 GB 系统内存；
- 2–4 TB NVMe；
- 7B–32B 模型；
- 64K–128K 上下文；
- 2–8 个并发 Agent；
- 支持连续批处理和上下文并行的推理后端。

这里要测量上下文压缩、摘要和恢复的实际开销。vLLM 的分页 KV 管理、chunked prefill 和 prefix caching 可以作为推理基础设施，但它们属于成本优化，不自动提供记忆或 Skill 的安全保证。[R7]

### 4.3 外部有效性与分布式执行

当机制在小模型和受控环境中成立后，再投入这一档检验模型、执行器、节点和工具服务变化下的外部有效性。

建议配置：

- 4–8 张 80 GB 级 GPU，或等效国产加速卡；
- 512 GB 以上系统内存；
- 高速互联；
- 32B–70B 模型；
- 多节点任务队列与状态存储；
- 独立的日志、版本和依赖图服务。

这一档可以研究：

- 大模型对污染和幻觉的敏感性；
- 多 Agent 之间的污染传播；
- 跨节点 Skill 组合；
- 状态恢复与分布式重放；
- 可信执行环境和设备侧隔离。

这一档属于外部有效性验证，不承担发现核心机制的任务。

### 4.4 国产卡适配条件

国产平台可以从探索级或机制验证级开始接入，也可以作为外部有效性环境。优先确认：

1. 是否支持目标模型的算子和量化格式；
2. 是否支持 32K 或更长上下文；
3. 是否支持 paged attention、连续批处理和 KV 管理；
4. 是否能稳定记录每轮输入、输出、工具调用和状态版本；
5. 多卡通信和显存管理是否适合长会话；
6. 是否提供设备侧隔离、密钥保护和远程证明能力；
7. 模型升级、记忆格式迁移和日志回放在国产平台上是否保持一致。

国产卡的研究价值可以来自长上下文状态管理、恢复开销、内存带宽、并发效率、证据记录和迁移一致性。模型移植结果需要与安全性质或生命周期成本关联，才具备研究解释力。

## 5. 实验系统结构

建议实现一个可重放的 Agent 状态实验框架：

```text
任务生成器
   ↓
Agent Runtime
   ├── 长上下文管理
   ├── Skill Loader
   ├── Memory Store
   ├── Policy / Provenance Store
   ├── Tool Broker
   └── Recovery Manager
   ↓
受控工具环境
   ├── 文件
   ├── 数据库
   ├── 网络服务
   └── 任务队列
```

每一次状态变化都记录：

```text
event_id
task_id
session_id
memory_or_skill_id
source_id
version
parent_dependencies
authority
scope
lifetime
transformation
evidence
uncertainty
state_schema
policy_version
model_version
retriever_version
tool_version
evidence_hash
verification_status
authorization
model_snapshot
prompt_hash
tool_call
effect
timestamp
```

日志需要支持确定性重放，至少能重放：

- 原始任务；
- 记忆检索；
- Skill 加载；
- 上下文压缩；
- 工具返回；
- 污染注入；
- 来源撤销；
- 恢复与重试。

## 6. 实验任务设计

### 6.1 长上下文规则保持

任务中设置多条明确规则：

- 只能修改某个目录；
- 禁止访问某类文件；
- 不能联网；
- 需要人工批准才能执行某工具；
- 只允许使用指定 Skill；
- 某条规则在第 N 轮发生更新。

控制变量：

- 上下文长度；
- 工具调用轮数；
- 摘要次数；
- 压缩策略；
- 规则出现位置；
- 规则之间的距离；
- 外部内容比例；
- 事实、程序、偏好、约束和权限的状态类型；
- 模型、检索器和记忆格式版本；
- 来源修订、时间冲突和规则撤销。

观测：

- 规则记忆准确率；
- 规则语义等价率；
- 工具调用违规率；
- 规则冲突后的最终采用结果；
- 规则更新后的旧规则残留率；
- 规则经过 0、1、2、4、8 次压缩后的保留曲线；
- 状态修订后的冲突解决准确率；
- 模型或记忆格式迁移后的规则保持率；
- 长度增加带来的延迟和 token 成本。

压缩基线需要包含：无压缩、统一摘要、类型化摘要、类型化摘要加受保护规则通道，以及摘要恢复后重新读取。StateComp 作为动态压缩时机基线，The Compaction Cliff 作为类型化保留基线。

### 6.2 Skill 污染与能力保留

准备三类 Skill：

1. 纯文本 Skill；
2. 带脚本和资源文件的 Skill；
3. 可以调用其他 Skill 或工具的组合 Skill。

每类 Skill 都需要配套原任务、参数变化任务、工具版本变化任务、模型迁移任务和留出任务。

污染方式：

- 加入隐藏指令；
- 改写权限范围；
- 加入条件触发行为；
- 伪造来源和版本；
- 将危险行为埋入依赖脚本；
- 利用 Skill 组合产生跨 Skill 影响；
- 审查后替换实际执行版本。
- 在 Skill 创建、存储、检索和激活四个入口分别注入。
- 通过正常经验、危险经验和拒答经验引入能力变化。

实验要比较：

- 无防御；
- 静态扫描；
- 运行时验证；
- 版本绑定；
- 影子执行；
- 组合依赖分析；
- 训练任务与留出任务；
- 参数变化和工具版本变化；
- 提议的恢复或隔离机制。

核心结果包括：

- Skill 污染成功率；
- 工具动作污染率；
- 正常任务完成率；
- 留出任务完成率；
- 高风险能力被隔离后的安全能力保留率；
- 过拒答率；
- 审查开销；
- 版本变化后的重新验证比例。
- 模型或记忆格式迁移后的能力保持率；
- 留出任务能力保持率；
- 过拒答率与能力侵蚀。

### 6.3 记忆污染传播

构造以下传播链：

```text
工具返回
→ 当前上下文
→ 短期摘要
→ 长期记忆
→ 经验规则
→ Skill 或计划
→ 工具动作
```

分别在每一层注入污染，比较污染能否跨层传播。

污染记录必须保留来源、动作权威、适用范围和父依赖，区分内容错误、权限误导和可触发动作的指令。

需要区分：

- 事实错误；
- 规则错误；
- 权限误导；
- 来源伪造；
- 过时信息；
- 局部正确但不适用的经验；
- 能诱发工具动作的指令。
- 时间冲突、来源修订和模型升级后的陈旧记忆。

### 6.4 污染恢复

设置以下变化事件：

- 原始文档被纠正；
- 原始来源被撤销；
- 工具版本发生变化；
- Skill 被发现存在风险。
- 模型版本或记忆格式发生变化。
- 计划依赖或外部状态发生竞态；
- 验证器信号过期、冲突或被撤销。

比较以下恢复和验证方式：

1. 直接继续使用；
2. 检索时过滤；
3. 删除受影响记忆；
4. 局部重建；
5. 全量重新读取或重新验证。
6. 受影响状态子图重建；
7. 回滚后重新演化；
8. Skill 降级为只读或人工审批。
9. 迁移到新模型或新记忆格式后进行兼容性验证。
10. 使用语义提交条件判断当前动作是否仍受影响；
11. 复用或撤销 MemGuard 式验证器信号；
12. 通过反事实重放判断变化是否真正改变动作安全性。

评价：

- 受影响状态定位准确率；
- 残余污染率；
- 合法信息误删率；
- 修复后的工具安全；
- 后续多轮任务效用；
- 留出任务效用；
- 恢复后再次演化的复发率；
- 模型迁移后的能力侵蚀；
- 安全操作误阻断率；
- 语义闸门精确率和召回率；
- 验证器信号的保持率与撤销延迟；
- 总 token、GPU 时间和端到端延迟。

## 7. 研究变量矩阵

| 维度 | 低档 | 中档 | 高档 |
|---|---|---|---|
| 会话长度 | 4 轮 | 16 轮 | 64 轮以上 |
| 上下文 | 8K | 32K | 128K |
| 记忆规模 | 100 条 | 1K 条 | 10K 条以上 |
| Skill 数量 | 1 | 4 | 16 以上 |
| 组合深度 | 1 层 | 2 层 | 4 层以上 |
| 污染密度 | 1 条 | 5% 状态 | 20% 状态 |
| Agent 数量 | 1 | 3 | 8 以上 |
| 变化频率 | 单次 | 每 20 轮 | 连续变化 |
| 模型规模 | 7B | 14B–32B | 70B 级 |
| 状态类型 | 事实 | 程序／偏好 | 约束／权限 |
| 压缩轮次 | 0 | 1–2 | 4–8 |
| Skill 评测 | 原任务 | 参数变化 | 工具变化／留出任务 |
| 污染入口 | 单点 | 创建／存储 | 检索／激活／组合 |
| 模型／记忆迁移 | 无变化 | 模型变化 | 模型＋检索器＋记忆格式变化 |
| 证据状态 | 已验证 | 部分验证 | 撤销／冲突／过期 |

第一轮实验只选择低档和中档，先建立因果关系。高档用于验证结论是否随规模和复杂度保持。

## 9. 研究假设

建议先验证以下七个假设：

### H1：规则保持会随上下文转换次数下降

摘要、压缩和重排次数增加后，规则语义等价率和动作约束能力下降；类型化状态与受保护规则通道可以减缓下降。

### H2：Skill 污染的风险主要来自跨阶段传播

污染在当前上下文中没有造成动作影响，并不代表它进入长期记忆或 Skill 后仍然没有影响。

### H3：隔离高风险能力可以保留较多合法能力

将 Skill 划分为可继续使用、需要审批和必须退役三类，可以获得比全量禁用更好的安全—效用平衡，但需要在参数变化、工具变化和留出任务上验证，并同时观察过拒答。

### H4：局部恢复的收益取决于依赖图质量

依赖记录准确时，局部修复可以降低重建成本；依赖丢失、后代状态未纳入或污染密度过高时，全量读取或全量退役可能更可靠。

### H5：安全性质会在不同状态载体之间发生非对称损失

同一规则从上下文进入摘要、记忆、经验和 Skill 时，事实内容、适用范围、动作权威和禁止事项的保留率可能不同；这种差异可以通过父依赖、来源证据和真实工具效果定位。

### H6：模型、检索器和记忆格式升级会造成不同程度的能力侵蚀

升级后原有记忆或 Skill 仍然可读取，不代表原有能力、规则约束和工具效果都能迁移。保留结构化来源、约束和执行证据的状态格式，可能比只保存自然语言摘要更容易迁移。

### H7：工具调用轨迹中的证据强度会影响恢复和审计结果

只记录模型输出或工具返回，难以判断批准意图是否真正对应外部效果。将来源、策略版本、工具参数、资源差分和执行结果绑定到同一轨迹后，受影响状态定位和恢复决策可能更稳定。

### H8：全局新鲜度闸门会增加安全操作误阻断，语义条件可以改善精度

仅依据状态是否过期、版本是否变化或依赖是否更新来全面阻断，可能把与变化无关的安全操作一并拒绝。结合计划前提、工具参数、外部状态差分和反事实重放的语义提交条件，有机会在保持违规拦截的同时降低误阻断。

### H9：验证器信号的持久化会降低重复检查成本，也可能传播错误结论

将验证结果写入记忆元数据可以减少重复审查和恢复延迟，但过期、来源不清或错误的验证信号会沿摘要、检索和 Skill 派生继续传播。需要测量信号保持率、撤销延迟和错误信号造成的能力损失。

这些属于待验证假设，实验可以证明它们不成立。

## 10. 推荐实验阶段

本节采用“探索、机制、外部有效性”三层，而非把所有工作锁定为单一路径。每层都可以形成阶段性成果，也可以根据复现结果调整投入。

### 探索层：低成本现象与状态表示

目标是确认规则、记忆、Skill 和工具效果之间是否存在可重放的状态差异。

- 16–48 GB GPU、云端模型或 API 模型均可；
- 3B–14B；
- 8K–64K 上下文；
- 4–32 轮；
- 1 个 Agent、受控本地工具和少量并发；
- 允许使用模拟工具和小规模数据。

交付物：

- 统一状态 schema；
- 可重放轨迹；
- 压缩、Skill 更新、来源修订和模型迁移的最小反例；
- 规则语义等价、能力侵蚀和工具效果差异的初步曲线。

### 机制层：跨状态转换与恢复

目标是识别安全性质在哪个转换上丢失、污染如何传播、恢复如何影响能力。

- 24–80 GB GPU 或等效国产卡；
- 7B–32B；
- 32K–128K 上下文；
- 4–16 个 Skill；
- 1–4 个工具型 Agent；
- 原任务、参数变化、工具变化、模型迁移和留出任务并行测试。

需要组合的基线包括 The Compaction Cliff、StateComp、TMA-NM、TRUSS、GSO、EvoSkill Injection、SafeEvolve-UP、来源撤销和记忆迁移方法。

交付物：

- 状态依赖和证据图；
- 四入口污染与跨状态传播结果；
- 局部修复、子图重建和全量重建对照；
- 能力保留、过拒答、能力侵蚀和长期复发曲线。

### 外部有效性层：跨模型、工具和硬件验证

目标是检验机制能否跨模型升级、检索器变化、工具版本变化、执行器和国产卡保持。

- 2–8 张 48–80 GB GPU 或等效国产卡；
- 14B–70B 作为扩展；
- 64K–128K 上下文；
- 多 Agent、任务队列、远端工具和独立状态服务。

交付物：

- 模型与记忆格式迁移报告；
- 多 Agent 状态同步和污染传播结果；
- 工具效果与批准意图的一致性报告；
- 同等安全目标下的推理、存储和恢复成本。

## 11. 当前最适合的研究切入

初期可从一个相对窄的切入口进入，研究问题保持向相邻状态载体扩展的能力：

> **当 Agent 的规则、记忆、Skill、harness／policy 或模型状态经过转换、升级和恢复后，如何判断其安全证据、动作约束和合法能力仍然一致？**

进入实验时优先选择规则—记忆—Skill 链条，逐步连接压缩、来源修订、模型迁移、工具效果和恢复：

1. 记录规则、记忆和 Skill 在每次转换中的来源、权威、适用范围和依赖；
2. 注入不同类型污染，覆盖 Skill 创建、存储、检索和激活，并记录时间冲突与来源修订；
3. 使用原任务、参数变化、工具变化、模型迁移和留出任务测量能力保留、过拒答与能力侵蚀；
4. 发生风险后比较局部修复、子图重建、重新读取、退役、回滚和恢复后再次演化；
5. 通过工具参数、资源差分和执行轨迹检查批准意图是否对应真实外部效果。

这样形成的研究资产包括状态表示、证据图、轨迹数据、攻击与变化生成器、恢复算法、迁移适配器和生命周期评测。硬件平台按探索、机制和外部有效性逐级增加，用于验证规模效应、模型迁移和国产卡上的执行成本。

### 13.2 仍值得验证的交叉空间

以下判断基于本轮检索，不代表全量查新已经结束：

1. **跨状态的规则安全保持。** The Compaction Cliff 已经覆盖按知识类型观察压缩、分解和检索失效；StateComp 已经覆盖压缩时机和强度。后续重点需要转向规则从上下文进入摘要、记忆、经验和 Skill 后，来源、权限、适用范围是否仍然约束真实工具动作。
2. **记忆到 Skill 的跨阶段污染。** 现有工作分别研究记忆投毒、Skill 安全和自演化审计；仍需验证同一污染从工具返回进入摘要、记忆、经验、Skill，再影响工具调用的完整因果路径。
3. **跨状态转换后的能力保留。** GSO 已经提出训练任务到留出任务的 Skill 泛化，SkillMisevo 的 SafeEvolve-UP 已经加入修复后的正常工作流检查。仍需测量规则、记忆和 Skill 多次转换以后，保留多少合法能力、误伤多少合法状态，以及恢复后能否在工具版本或权限变化下继续工作。
4. **多次变化的恢复。** 来源更正、权限收紧、工具版本变化、Skill 更新、上下文重启交错后的增量重验证与完整重建，仍需要统一成本和安全评价。
5. **规则与幻觉的联合评测。** 事实错误、过时经验、权限误导和动作越权需要分别标注，不能归并成单一的“污染率”。
6. **时间冲突与来源修订。** STALE 已经把陈旧记忆和跨轮次冲突作为评测对象，仍需验证冲突修订如何沿记忆—Skill—计划链路传播，以及撤销后的动作权威何时失效。
7. **模型升级与记忆迁移。** 当前可直接借鉴的是 Text2Mem 的操作 schema、REMM 的证据链接和 CPE 的能力保持评价；模型升级、检索器变化和记忆格式变化仍应作为开放环境变量，分别测量安全证据、规则约束和合法能力是否同步迁移。
8. **工具效果的证据闭环。** AgentTrace、Counterfactual Trace Auditing、TRACE 和 REMM 提供轨迹、反事实、运行时规则和证据链接组件，仍需将批准意图、工具参数、资源差分和后续 Skill 更新连成因果证据。
9. **能力侵蚀与恢复后的持续工作。** CPE 提示自演化可能遗忘原有能力；“Stale Does Not Mean Unsafe”进一步提示全局新鲜度闸门会造成安全操作误报。恢复实验需要同时关注能力退化、误阻断、再次演化后的复发和语义闸门精度。
10. **验证器信号的生命周期。** MemGuard 提供了将验证结果写入记忆元数据的思路，仍需研究验证器信号在摘要、检索、Skill 派生和归档后是否保持可解释、可撤销和不被污染。

### 13.3 现有工作的共同方法资产

查新结果说明，后续工作可以直接吸收以下方法资产：

| 方法资产 | 来源工作 | 建议继承方式 |
|---|---|---|
| 来源与能力分离 | SAGE-Mem、TMA-NM、FIDES | 事实支持、数据可用性与动作授权分开记录 |
| 记忆写入前检查 | A-MemGuard、Before It Persists | 作为进入长期存储的第一道门，记录拒绝原因 |
| 受控影子执行 | TRUSS、SkillRelayGuard、SafeEvolve | 在真实执行前收集轨迹和潜在副作用 |
| 能力依赖图 | ColluSkill、SafeEvolve | 从记忆到 Skill、从 Skill 到动作保留派生关系 |
| 反事实定位 | MemAudit | 对受影响状态做删除、替换和重放比较 |
| 生命周期成本 | When Evidence Changes | 计入建立、更新、修复和后续使用的总成本 |
| 攻击与正常效用并测 | AgentLAB、MemSecBench、SkillsBench | 同时报告攻击成功、合法任务完成和误伤 |
| 时间冲突修订 | STALE | 对陈旧、冲突和来源更正记录修订前后状态 |
| 记忆操作与状态迁移 | Text2Mem、REMM | 用显式操作和证据链接记录记忆派生、修订、回滚和恢复 |
| 工具轨迹与反事实证据 | AgentTrace、Counterfactual Trace Auditing、TRACE | 将来源、策略版本、工具参数、资源差分和行为影响绑定 |
| 能力侵蚀与误阻断 | CPE、GSO、Stale Does Not Mean Unsafe | 在原任务、留出任务、恢复后连续任务中测量能力变化和安全操作误报 |
| 验证器信号治理 | MemGuard | 记录验证信号的来源、有效期、传播、撤销和复核成本 |

这些资产可以组成研究底座。组合时需要保留每个方法的适用条件和保证边界，研究贡献落在跨阶段转换、环境变化和恢复后的组合性质。

### 13.4 已有强基线与区分条件

以下工作适合作为直接基线：长时域攻击 benchmark、来源绑定授权、记忆写入过滤、Skill 静态扫描、LLM 审查器、经验到 Skill 生成、多 Agent 沙箱、上下文和 KV 优化。它们不构成研究主题的禁区。

继续研究同一主题时，至少需要在以下维度中明确变化：

1. 状态载体：上下文、摘要、记忆、经验、Skill、harness、模型状态或外部工具状态；
2. 状态转换：压缩、合并、检索、派生、组合、迁移、撤销或恢复；
3. 威胁模型：工具返回、跨会话、跨 Agent、模型升级、工具升级或来源修订；
4. 保证对象：来源、动作权威、规则语义、合法能力、外部效果或恢复成本；
5. 评价方法：留出任务、反事实重放、轨迹证据、能力侵蚀或长期复发。

仅替换模型、数据集或提示词，区分度有限；在状态转换、保证对象或评价方法上形成新连接，可以继续沿用已有主题并产生延伸。

### 13.5 建议聚焦的交叉主线

建议把研究主线表述为：

> **长期运行 Agent 的持久状态在载体转换和环境变化中的安全演化、能力保留与可恢复性。**

规则和 Skill 仍是第一阶段的主要载体，记忆、harness／policy、模型升级、工具版本和外部状态可以沿同一状态链逐步接入。

具体分解为四条可以并行、也可以连续推进的问题：

1. **转换保真。** 规则、来源、适用条件和授权从上下文进入摘要、记忆、经验和 Skill 后，哪些信息被丢失，如何检测；
2. **影响边界。** 被污染的状态如何跨越不同层，最终影响哪些工具动作，什么拦截点能够保留更多合法能力；
3. **变化恢复。** 来源、工具、权限、模型或 Skill 变化后，如何定位受影响状态、局部修复或退役，并比较完整生命周期成本；
4. **能力迁移与证据闭环。** 模型升级、记忆格式迁移和工具执行后，安全证据、规则约束与合法能力是否同步迁移，如何通过轨迹和外部状态差分验证。

每一项都需要可重放轨迹和分层工具效果支撑。探索阶段可以使用模拟工具发现机制，机制阶段再连接受控真实工具，外部有效性阶段验证远端工具、模型升级和国产卡。仅在文本问答层测“记住规则”或“判断是否安全”，研究结论不足以覆盖 Agent 的实际行为。


## 14. 分阶段工作指南

以下周期是资源安排参考，允许并行和回退。某一阶段形成边界结果后，可以转入其他分支，不需要等待全部前置阶段完成。

### 阶段 0：查新、复现和实验底座（建议周期 0–4 周）

**目标。** 确认研究对象、复现条件和已有方法边界，避免把已解决问题重新实现。

**固定条件。**

- 选择一个 Agent 宿主；
- 选择一个 7B–14B 开源模型；
- 选择 3 类工具：文件、数据库、本地网络；
- 选定 2 个合法任务域：代码仓库维护和研发文档处理；
- 固定模型权重、解码参数、工具版本和安全策略；
- 建立事件日志与确定性重放。

**必须实现。**

1. 任务生成器；
2. 上下文和摘要模块；
3. 记忆存储与检索；
4. Skill 加载器；
5. 工具 Broker；
6. 资源端效果记录；
7. 版本和来源记录；
8. 污染注入器；
9. 重放与差分比较器。

**交付物。**

- 10–20 个基础任务；
- 100 条以上可重放轨迹；
- 每条轨迹的状态、来源和工具效果；
- 现有基线的可运行版本；
- 一份查新矩阵：已有保证、假设、评测范围和未覆盖点。

**进入下一步的条件。**

- 能重放同一任务并得到可解释的工具效果；
- 能区分规则丢失、事实错误、来源失效和权限违规；
- 至少复现一个已有方法，或记录清楚其在当前环境中无法复现的原因；
- 已经形成一个可检验的状态差异或反例。

复现失败可以转化为环境、模型、工具或论文假设的边界记录，不需要把所有基线修复到完全一致后再开展机制探索。

**硬件。** 1 张 16–48 GB GPU，64–128 GB 内存，1–2 TB NVMe；也可以使用云端／API 模型配合本地状态和工具环境。

### 阶段 1：长上下文规则保持（建议周期 5–10 周，可并行）

**研究问题。**

> 上下文增长、压缩、摘要和恢复会怎样改变既有规则的语义等价率与动作约束能力？

**规则集合。**

- 资源访问规则；
- 工具白名单；
- 禁止数据出口；
- 人工审批条件；
- 任务截止时间；
- Skill 适用范围；
- 动态更新和撤销规则。

**变量矩阵。**

| 变量 | 设置 |
|---|---|
| 上下文 | 8K、32K、64K |
| 轨迹长度 | 4、16、32、64 轮 |
| 摘要次数 | 0、1、3、8 |
| 规则位置 | 开头、中间、末尾、摘要中 |
| 外部内容 | 10%、30%、60% |
| 压缩方法 | 无压缩、截断、滑窗、普通摘要、类型化摘要、受保护规则通道 |
| 规则变化 | 无变化、收紧、撤销、替换、来源修订、时间过期 |
| 计划状态 | 无依赖变化、依赖更新、工具参数变化、外部状态竞态 |
| 状态类型 | 事实、程序、偏好、约束、权限 |
| 压缩轮次 | 0、1、2、4、8 |

**主要指标。**

- Rule Retention；
- 规则语义等价率；
- 规则冲突错误率；
- 规则更新生效延迟；
- 违规工具调用率；
- 实际外部效果违规率；
- 计划新鲜度违规率；
- 安全操作误阻断率；
- 语义提交闸门精确率和召回率；
- token、GPU 时间和 p95 延迟。

**消融实验。**

1. 原始规则直接放入系统上下文；
2. 规则放入结构化状态；
3. 规则带来源和版本；
4. 规则进入统一摘要；
5. 类型化摘要；
6. 类型化摘要加受保护规则通道；
7. 规则在恢复后重新读取；
8. 只观察文本回答；
9. 连接受控工具后再测；
10. 全局新鲜度闸门与语义提交条件对照；
11. 验证器信号不持久化与持久化对照。

**阶段产出。**

- 规则保持曲线；
- 规则丢失的因果分类；
- The Compaction Cliff 和 StateComp 对照结果；
- 压缩策略的安全—成本曲线；
- 一个可复现的长上下文规则评测集。

**立项判断。** 阶段 1 可以产生三类结果：发现规则语义等价率与工具效果之间的稳定差异；证明某种现有方法在特定边界内足够有效；或者得到可迁移的负结果和测量资产。后两类结果都可以用于决定后续进入 Skill、恢复或模型迁移分支。

**硬件。** 1 张 24–48 GB GPU；需要 64K 以上上下文时再使用 80 GB GPU、量化模型或分段执行。

### 阶段 2：Skill 污染、组合与能力保留（建议周期 11–20 周，可并行）

**研究问题。**

> 当污染进入 Skill 生命周期、Skill 组合或 Skill 版本更新后，系统能否限制风险，同时在留出任务和真实工具上保留合法能力？

**Skill 类型。**

1. 文本流程 Skill；
2. 带脚本的 Skill；
3. 带资源文件的 Skill；
4. 工具调用 Skill；
5. 多 Skill 组合；
6. 跨会话更新 Skill。

Skill 评测需要区分原任务、参数变化任务、工具版本变化任务和留出任务。

**污染类型。**

- 隐藏指令；
- 权限范围扩大；
- 条件触发行为；
- 伪造来源或版本；
- 依赖脚本变化；
- 多 Skill 串联；
- 审查后替换执行版本；
- 旧 Skill 在新任务中继续被加载。
- Skill 创建、存储、检索和激活四个入口的分别注入。

**对照方法。**

- 无防御；
- 静态扫描；
- 运行时检查；
- 影子执行；
- 版本绑定；
- Skill 依赖图；
- 来源与授权绑定；
- 风险 Skill 隔离和退役。
- GSO 留出任务；
- EvoSkill Injection 四入口攻击；
- SafeEvolve-UP 修复后效用检查。

**能力分级。**

```text
正常使用
受限使用
人工批准
只读分析
退役重建
```

**指标。**

- Skill 污染成功率；
- 工具动作违规率；
- 正常任务完成率；
- 留出任务完成率；
- 安全能力保留率；
- 过拒答率；
- 合法 Skill 误杀率；
- 组合深度与风险增长；
- 版本变化后的重验证比例；
- 单次检查和累计检查成本。

**关键消融。**

1. 只扫描 Skill 文本；
2. 扫描 Skill 与依赖；
3. 影子执行；
4. 真实工具执行；
5. 单 Skill；
6. 多 Skill 组合；
7. 同版本；
8. 审查后版本替换；
9. 原任务与留出任务；
10. 修复后再次演化。

**阶段产出。**

- Skill 风险传播图；
- 安全能力保留曲线；
- 组合和版本变化的失败模式；
- 对已有 SkillSafetyBench、SkillsBench 的扩展场景。
- GSO 和 EvoSkill Injection 的复现实验记录。

**立项判断。** 阶段 2 优先寻找跨会话、跨 Skill、工具版本变化或模型迁移下的独立失效模式。若现有方法已经覆盖某一场景，就把该场景作为基线，并转向证据迁移、能力侵蚀、过拒答或恢复成本。

**硬件。** 1 张 24–80 GB GPU 或 2 张 24–48 GB GPU；7B–32B 模型；本地数据库和任务队列。留出任务和工具效果验证可以先使用小模型和受控工具。

### 阶段 3：记忆到 Skill 的跨阶段传播（建议周期 21–32 周，可与阶段 1、2 交叉）

**研究问题。**

> 同一污染从工具返回进入上下文、摘要、长期记忆、经验规则和 Skill 后，影响范围如何变化？

**传播链。**

```text
工具返回
→ 当前上下文
→ 摘要
→ 长期记忆
→ 经验规则
→ Skill
→ 计划
→ 工具动作
```

**实验方式。**

- 在每个节点分别注入同类污染；
- 保持污染内容、任务和模型不变；
- 保留每个节点的来源、权威、适用范围和父依赖；
- 记录首次影响轮次；
- 记录污染是否被摘要放大或削弱；
- 记录污染是否进入 Skill；
- 记录最终工具效果；
- 对每个节点执行隔离、修复和恢复后再次演化。

**核心指标。**

- 传播概率；
- 传播深度；
- 首次动作影响时间；
- 污染半衰期；
- 跨会话持续时间；
- 工具效果影响率；
- 每个拦截点的误拒绝率；
- 计划依赖缺失率；
- 计划新鲜度违规率；
- 验证器信号跨层保持率；
- 语义提交闸门的安全操作误报率；
- 留出任务能力保留率；
- 修复后复发率；
- 拦截和修复成本。

**研究方法。**

1. 依赖图对照；
2. 来源标签对照；
3. 结构化摘要对照；
4. Skill 生成前后对照；
5. 只允许回答、不允许执行；
6. 允许受控工具执行；
7. 单 Agent 与多 Agent 对照；
8. 原任务、参数变化、工具版本变化和留出任务对照。

**阶段产出。**

- 记忆—Skill—动作传播模型；
- 污染进入不同状态层后的影响差异；
- 最小有效拦截点；
- 跨阶段安全属性和误伤边界。

**硬件。** 1 张 48–80 GB GPU 或 2 张 24–48 GB GPU；7B–32B 模型；1–4 个并发 Agent。跨 Agent 与远端工具作为扩展变量。

### 阶段 4：污染恢复与能力降级（建议周期 33–46 周，可提前启动）

**研究问题。**

> 污染或来源变化发生后，系统如何定位受影响状态，选择修复范围，并尽可能保留合法能力？

**变化事件。**

- 来源内容更正；
- 来源撤销；
- 工具版本升级；
- Skill 版本替换；
- 权限收紧；
- 记忆发现污染；
- 任务中断和恢复；
- 依赖日志部分缺失；
- 模型版本升级；
- 检索器或记忆格式升级。

每个变化事件都需要追踪受影响状态及其后代，不能只检查直接来源或单个 Skill 文件。

**恢复策略。**

1. 检索时过滤；
2. 条目退役；
3. 局部修复；
4. 依赖范围重建；
5. 重新读取原始来源；
6. Skill 降级为只读；
7. 全量重新验证；
8. 任务暂停并等待人工确认；
9. 受影响状态子图重建；
10. 回滚后重新演化。

**恢复判据。**

- 原始来源仍有效；
- 关键依赖可重放；
- 新版本工具通过安全检查；
- 规则和授权仍匹配；
- 未发现残余污染；
- 合法任务效用达到阈值；
- 留出任务效用达到阈值；
- 恢复后再次演化没有复发。

**指标。**

- 受影响状态定位召回率；
- 定位误报率；
- 残余污染率；
- 合法状态误删率；
- 恢复后的任务完成率；
- 修复后连续任务完成率；
- 恢复后再次演化的复发率；
- 过拒答率；
- 安全操作误阻断率；
- 语义闸门精确率；
- 验证器信号撤销延迟；
- 恢复延迟；
- GPU 时间、token 和存储；
- 重复变化后的稳定性。
- 模型或记忆格式迁移后的能力保持率；
- 轨迹证据完整度；

**阶段产出。**

- 状态影响分析算法；
- 局部修复和全量重建对照；
- 能力降级策略；
- 完整生命周期成本模型。

**立项判断。** 阶段 4 优先比较局部修复、子图重建和全量重建在不同证据完整度下的边界。局部修复有效时研究其保证和成本；局部修复失效时研究依赖证据缺口、能力降级和安全停止条件。

**硬件。** 1–4 张 48–80 GB GPU 或等效国产卡；14B–32B 模型即可完成机制验证，32B 以上模型用于外部有效性扩展。

### 阶段 5：多 Agent、分布式和国产卡验证（建议周期 47–64 周，按需启动）

**目标。** 验证核心机制能否跨执行器、工具服务和硬件平台保持。

**扩展变量。**

- 1、3、8 个 Agent；
- 本地工具和远端工具；
- 共享记忆和隔离记忆；
- 单节点和多节点；
- NVIDIA 与国产加速卡；
- 7B、14B、32B；
- 32K、64K、128K 上下文。

**重点测量。**

- 状态同步延迟；
- 跨节点污染传播；
- 恢复时的一致性；
- 多 Agent Skill 组合；
- 设备显存和内存带宽；
- p99 延迟与吞吐；
- 同等安全目标下的执行成本。

**硬件。**

- 4–8 张 80 GB 级 GPU 或等效国产卡；
- 512 GB 以上内存；
- 高速互联；
- 独立状态存储、日志和任务队列。

**进入条件。** 阶段 5 通常在阶段 2–4 形成可重放现象后启动，也可以选择一个小规模迁移试验提前验证国产卡、模型升级或远端工具的工程边界。大规模硬件用于外部有效性，不承担发现核心机制的任务。

1. 把“规则—Skill”写得过于封闭，容易忽略记忆格式、harness／policy、模型升级、工具版本和外部状态；

修正后的研究中心是：

> **长期运行 Agent 的持久状态在载体转换和环境变化中的安全演化、能力保留与可恢复性。**

规则和 Skill 作为第一阶段的主要载体，记忆、harness／policy、模型升级和工具状态作为可连接的后续载体。研究可以从压缩、污染、迁移、证据闭环或恢复中的任一切入口开始，只要能够把状态转换、保证对象和真实效果连接起来。

首年采用探索层、机制层和外部有效性层的弹性推进。小模型、模拟工具和单卡实验用于发现机制，受控真实工具用于确认行为，跨模型、分布式和国产卡用于验证迁移与成本。每个阶段允许形成正结果、边界结果或可复用的负结果，不把单一实验门槛作为主线成立的唯一依据。

## 16. 相似论文精读：方法差异与可继承内容

本节对长期记忆、Skill 演化、计划新鲜度、轨迹审计、能力保持、精确闸门和相邻 KV 基础设施工作进行方法层面的区分。它们研究对象、控制位置和安全保证不同，因此保留本规划的主线：

> 长期运行 Agent 的持久状态在载体转换和环境变化中的安全演化、能力保留与可恢复性。

### 16.1 TMA-NM：解决“来源能否获得动作权威”

**问题定义。** TMA-NM 研究长期记忆中的来源权威是否会在摘要、工具传递或其他派生过程中被错误提升，攻击目标是让不可信记忆驱动后续的 consequential action。[R6]

**核心方法。**

1. 写入时绑定来源和 `act_class`；
2. 权威随来源不可提升；
3. 只有可信来源或独立可信佐证可以提升动作资格；
4. 对每次写入、提升和决策记录防篡改日志；
5. 用 TLA+ 模型表达安全性质。

论文的关键贡献是把“内容看起来正常”与“内容有权驱动动作”分开。其多轮实验说明来源标签可以跨轮次传播，动作闸门能阻止不可信值直接触发后果性动作。[R6]

**它没有覆盖的内容。**

- 跨 Agent 共享记忆被明确排除；
- 自由文本回答仍可能受到不可信内容影响；
- 保证依赖正确的来源标记与独立可信源；
- 深层结构化 payload 和纯上下文重构的值归属仍是后续问题；
- 它保持记忆权威，但不研究摘要、经验或 Skill 的功能退化；
- 它不研究来源撤销后哪些派生对象必须重建。

**对本方向的借鉴。**

- 直接继承 `origin`、`act_class`、独立佐证和动作闸门作为强基线；
- 用它区分“规则被记住”和“规则有权约束动作”；
- 将 TMA-NM 的不可提升规则延伸到 Skill 生成和版本更新；
- 研究规则经过摘要、合并和 Skill 化后，哪些派生状态仍然继承原权威；
- 研究来源撤销后，TMA-NM 的标签如何沿依赖图失效。

因此，TMA-NM 与本方向属于**授权语义层和状态演化层**的关系。它不替代对长上下文规则保留、Skill 污染和恢复的研究。

### 16.2 TRUSS：解决“Skill 候选能否被证据化验证”

**问题定义。** TRUSS 研究自动生成的 Skill 是否同时提升任务效果并满足安全属性，重点是候选 Skill 在被部署前的静态检查、受控执行和修订。[R8]

**核心方法。**

1. 冻结完整 Skill 包，包括指令文档和可执行资源；
2. 为每个候选分配内容摘要；
3. 静态检查功能声明和安全属性；
4. 通过 brokered tool 在 disposable sandbox 中执行；
5. 记录带来源的轨迹；
6. 将失败回溯到 Skill 内容；
7. 每次修订后重新静态检查和重新执行。

TRUSS 使用九类安全属性，包括控制完整性、访问边界、执行完整性、生命周期隔离、资源边界、证据完整性、权威完整性、组合完整性和事务安全。[R8]

它的关键方法价值在于：**静态分析和运行时证据必须共同决定 Skill 是否合格。** 单纯检查文本会遗漏多步执行后才出现的副作用；单纯看最终任务结果也会遗漏中间违规行为。[R8]

**它没有覆盖的内容。**

- 候选 Skill 主要是在部署前被检查；
- 每次修订都会重新进入完整检查流程，增量验证没有展开；
- 评测依赖预设场景、property observers 和 benchmark verifier；
- 论文明确把更广执行场景和更多属性观察器留作后续；
- 长上下文压缩、长期记忆、来源撤销和恢复不属于核心对象。

**对本方向的借鉴。**

- 继承“完整 Skill 包冻结”和“执行轨迹绑定版本”的做法；
- 继承功能效果与安全效果同时评价；
- 把 `Function and Safety Record` 扩展为跨会话状态记录；
- 研究 Skill 经过经验更新、工具升级或规则收紧后，是否需要完整重验；
- 设计增量验证，比较完整重验、局部重验和风险退役；
- 把 Skill 的安全证据与记忆来源和任务规则绑定。

因此，TRUSS 与本方向属于**Skill 证据验证层和长期演化层**的关系。直接复现其静态—动态检查属于基线；长期变化后的证据失效和能力保留属于可继续研究的空间。

### 16.3 SafeEvolve（arXiv:2609.02786）：解决“经验如何驱动安全行为共演化”

**问题定义。** SafeEvolve 研究 Agent 从多步执行经验中更新安全 harness，并通过 SFT 和 RL 让策略学习使用这些更新后的安全组件。[R9]

**核心方法。**

1. 从完成的 on-policy 轨迹提取安全经验；
2. 将经验编译为版本化 safety prompt 和层次化 Skill；
3. 通过 harness-use SFT 训练 Agent 使用这些组件；
4. 通过 harness-augmented RL 将安全行为内化到策略；
5. 使用分解后的任务效用和安全奖励；
6. 动态检索 Skill，维护最近和任务相关的安全经验。

SafeEvolve 的重要贡献是指出：只更新外部 harness，模型可能不会稳定执行新增规则；只更新模型策略，又可能无法适应新出现的环境攻击。因此它研究的是 harness 和 policy 的联合适应。[R9]

**它没有覆盖的内容。**

- 重点是安全行为学习，记忆来源权威属于另一层控制问题；
- 其安全更新主要由轨迹和 verifier reward 驱动；
- 研究对象使用 AgentDojo、AgentDyn、AgentHarm 等环境；
- 主实验使用 Qwen3/3.5-4B，策略训练使用四张 H200；
- 长期记忆项、Skill 来源、工具版本、权限撤销和恢复不属于核心实验；
- 未来工作明确提出扩展到其他更新机制和更长的自然任务流。

**对本方向的借鉴。**

- 继承“轨迹级安全—效用联合奖励”；
- 继承版本化 harness 和动态 Skill 检索；
- 将安全经验与来源、规则版本和任务条件绑定；
- 研究安全经验是否会在摘要或 Skill 化时丢失限制条件；
- 研究策略内化后，如何定位其来源和执行证据；
- 比较规则仍在外部状态、被编译进 Skill、被内化进模型三种状态的可恢复性。

因此，SafeEvolve 与本方向属于**行为适应层和状态证据层**的关系。我们可以使用它作为动态适应基线，重点研究“更新依据是否可信、变化后如何回滚、哪些能力可以安全保留”。

### 16.4 Practice Makes Unsafe（arXiv:2608.12851v2）：解决“自演化 Skill 会不会积累持久风险”

**问题定义。** 这项工作把 Skill 自演化分解为 authoring、retrieval、execution 三个生命周期门，研究少量恶意或有问题的任务是否会形成跨任务持久危害。[R10]

**核心方法。**

1. 构造 episode-scoped 的 Skill 进化环境；
2. 在恶意任务、正常任务和后续探测任务之间重置会话；
3. 导出进化后的 Skill 文件；
4. 在 clean executor 中重新加载；
5. 分别测量在线攻击、Skill 文件风险、后续检索风险和 carryover harm；
6. 使用 repair、lineage attribution、retirement 和容量淘汰控制风险。

这项工作的突出贡献是将“任务当时成功”与“后续 Skill 是否安全”分开。论文中的 SafeEvolve 在 Skill 写入和后续检索时检查风险；SafeEvolve-UP 在此基础上增加保留原有正常工作流的效用检查，专门观察修复对合法任务能力的影响。它还说明混合正常经验未必能清除已经形成的风险，持久风险会跨更新继续存在。[R10]

**它没有覆盖的内容。**

- 重点是 Skill library 的持续适应，记忆、policy 和多模态更新留作后续；
- 任务主要是 executable computer-use episodes；
- 尚未覆盖自然长期部署中的多种更新机制；
- 没有将长上下文摘要造成的规则丢失作为主要变量；
- 恢复主要围绕 Skill 删除、修复和退役，未深入来源变更后的依赖重建；
- 该论文已经给出 SafeEvolve／SafeEvolve-UP 的 Skill 修复、归因和效用检查，不能再把单个 Skill 的“修复—归因—退役”流程本身作为新意。

**对本方向的借鉴。**

- 继承 M/B/P 任务结构和 clean reload；
- 继承在线行为、演化工件和后续 carryover 三组指标；
- 把长上下文、摘要、记忆和 Skill 连接到同一条生命周期；
- 将恢复对象从单个 Skill 扩展为受影响的状态子图；
- 增加合法能力保留率和修复后连续任务完成率；
- 增加来源撤销、工具升级、权限收紧和多次变化。

因此，这项工作与本方向属于**Skill 生命周期评测层**的关系。它让我们的实验必须包含跨会话和后续复用，但没有覆盖“长上下文规则—记忆—Skill—动作”的完整状态转换链。

### 16.5 The Compaction Cliff、StateComp、GSO 与 EvoSkill Injection：新增直接近邻与边界

**The Compaction Cliff。** 该工作按事实、程序、偏好和约束等类型分析长期记忆在压缩、分解和检索后的质量变化。它是规则保留实验的直接基线，说明普通摘要质量不能代表安全约束保持。[R13]

**StateComp。** 该工作根据 Agent 当前状态选择压缩时机和压缩强度，以长时域效用和 token 成本为主要目标。它适合提供动态压缩基线，安全约束的来源、权威和动作效果需要额外验证。[R14]

**GSO。** 该工作使用留出任务测试自演化 Skill 的泛化，提醒我们把原任务重放作为能力保留的最低测试，而非完整结论。[R15]

**EvoSkill Injection。** 该工作覆盖 Skill 创建、存储、检索和激活四个生命周期入口。它适合提供污染攻击基线，后续实验需要追踪污染对计划、工具参数和外部状态的影响。[R16]

**Experience-Driven Self-Evolving Agents。** 该工作将执行经验、拒答经验、安全收益和过拒答放在同一评价框架中。它提示能力保留必须包含正常任务、留出任务和过拒答指标。[R17]

**STALE。** 该工作把时间冲突、陈旧记忆和来源修订纳入长期 Agent 记忆一致性评测。它补充了“记忆内容是否正确”之外的时间有效性问题，后续可以研究冲突修订如何沿 Skill、计划和动作继续传播。[R20]

**Supersede、MemStrata、PlanFence 与 Text2Mem。** 这些工作分别从记忆替代、双时间有效性、计划依赖和可执行记忆操作切入。它们共同提示长期状态需要区分事实发生时间、系统接收时间、当前有效性、记忆操作类型和计划依赖；后续可以研究这些字段在摘要、Skill 派生和动作提交后是否仍然一致。[R21–R24]

它们的共同边界是：时间字段、记忆操作或计划依赖通常由系统显式维护，尚未充分回答恶意内容如何伪造这些字段、字段在压缩和 Skill 化后如何失真，以及字段失真后哪些真实工具动作仍可安全提交。这里可把“字段完整性”和“动作效果”放在同一条可重放轨迹中验证。

**AgentTrace、Counterfactual Trace Auditing 与 TRACE。** 这些工作把工具调用、来源、策略版本和 Skill 对行为的影响组织成结构化轨迹、反事实比较或运行时规则。它们适合作为工具效果验证、规则生效验证和恢复定位的证据层，避免只依赖模型输出或工具自报结果。[R25–R27]

它们的共同边界是：轨迹、反事实和运行时规则分别回答“发生了什么”“某个 Skill 是否改变了行为”“纠正如何生效”，跨越多个状态载体的统一因果链仍需要自行构造，尤其是摘要、记忆、Skill、计划和外部状态之间的父子依赖与撤销传播。

**CPE 与 REMM。** CPE 测量自演化过程中的能力侵蚀和遗忘；REMM 通过证据链接和可修订任务状态支持定向恢复。两者共同提示恢复实验需要区分状态找回、能力找回和安全约束找回，并观察恢复后继续演化是否再次退化。[R28–R29]

它们的共同边界是：能力退化和可修订状态已有测量或机制，但恢复范围如何由跨层证据自动确定、恢复后如何避免旧验证信号重新激活、以及模型和工具变化同时发生时如何给出可解释的降级路径，仍可作为交叉问题。

**Stale Does Not Mean Unsafe 与 MemGuard。** 前者将失效竞态和无害竞态区分开，并使用语义提交条件、反事实重放和精确闸门降低误报；后者把验证器信号保存到记忆生命周期，使验证结果能参与后续检索、冲突处理和归档。它们共同修正“只要状态变旧就全面阻断”的实验假设，要求将安全操作误报、验证信号传播和撤销成本列为一等指标。[R30–R31]

它们的共同边界是：精确闸门依赖可观察的状态差分和可靠的反事实重放，验证器信号依赖初始判断正确且生命周期元数据未被篡改。研究中需要专门构造不可观测差分、错误信号、信号过期和信号冲突，测量系统能否退回人工审批或局部重验。

这些方法分别控制压缩策略、Skill 泛化、污染入口、时间一致性、计划新鲜度、记忆操作、轨迹证据、能力侵蚀、语义闸门精度和验证器信号生命周期。它们仍然没有覆盖“规则—记忆—Skill—计划—动作—外部状态—修订”之间的完整证据连续性，因此可以沿状态转换、环境变化、误报控制和恢复机制连接成新的研究链条。

### 16.6 KVGov 与 CachePrune：相邻的 KV 基础设施安全，但控制层不同

**KVGov。** 该工作把多租户 KV 前缀缓存的根因定义为缓存键没有绑定请求主体，使用按主体派生的 HMAC salt 隔离缓存命名空间，并用审计调度器处理剩余风险。它控制的是**缓存条目能否跨主体命中**，安全证据来自缓存键构造、时延测量和攻击成功率。[R11]

**CachePrune。** 该工作先识别敏感 token，再从非敏感片段中推导可复用 KV 段，使用上下文相关的可复用性判断和滚动哈希检索处理任意位置、可变长度的片段。它控制的是**哪些 token 对应的 KV 可以被选择性复用**，同时评价隐私泄露、生成质量和 TTFT。[R12]

两者都可以借鉴“安全属性与性能收益一起测量”的实验习惯，但它们没有研究：

- 长上下文压缩后系统规则是否仍然有效；
- 工具返回如何进入记忆，再转化为经验或 Skill；
- Skill 组合后来源、限制条件和动作权威是否保留；
- 来源、工具版本或权限变化后，哪些派生状态需要恢复。

因此，KVGov 和 CachePrune 适合作为推理后端、国产卡适配和性能成本的背景基线；它们的缓存键隔离、敏感片段选择和真实 TTFT 测量可以支持基础设施实验，研究主线仍放在 Agent 安全状态的跨阶段转换与恢复。

## 18. 基于精读结果优化实验对照

阶段 1 的规则保持实验需要同时加入 The Compaction Cliff、StateComp、STALE 和 TMA-NM 的对照：

1. 纯文本规则；
2. 结构化规则；
3. 结构化规则加来源标签；
4. 来源标签加动作闸门；
5. 无压缩、统一摘要和类型化摘要；
6. 类型化摘要加受保护规则通道；
7. StateComp 动态压缩时机；
8. 时间冲突与来源修订；
9. 经过摘要和恢复；
10. 连接真实工具效果。

阶段 2 的 Skill 实验需要加入 TRUSS 的完整 Skill 包冻结、GSO 的留出任务、EvoSkill Injection 的四入口攻击和内容摘要绑定：

1. 只检查 Skill 文本；
2. 检查文本和脚本；
3. 影子执行；
4. 版本绑定；
5. 组合依赖图；
6. 变化后的完整重验；
7. 变化后的增量重验；
8. 风险能力隔离和合法能力保留；
9. 原任务、参数变化、工具版本变化和留出任务；
10. 修复后再次演化。

阶段 3 的跨阶段实验需要加入 SkillMisevo 的 M/B/P 结构、SafeEvolve-UP 的修复后效用检查、Experience-Driven 的过拒答指标、Supersede／MemStrata／PlanFence／Text2Mem 的状态操作与计划新鲜度对照，并把 SafeEvolve（2609.02786）的版本化 harness—policy 更新作为另一条基线：

1. 恶意暴露；
2. 正常经验更新；
3. 跨会话 clean reload；
4. 后续探测；
5. 来源变化；
6. 工具版本变化；
7. 权限收紧；
8. Skill 退役和局部恢复；
9. 模型、检索器或记忆格式变化；
10. 恢复后再次演化；
11. AgentTrace 的轨迹证据和 Counterfactual Trace Auditing 的行为差分；
12. TRACE 的纠正编译和运行时规则生效；
13. Stale Does Not Mean Unsafe 的语义提交条件与反事实重放；
14. MemGuard 的验证器信号跨检索、摘要、冲突处理和归档传播。

这样做的目的在于分别使用各类已有工作的强测试方法，观察它们在“长上下文转换—记忆派生—Skill／harness 更新—模型或工具迁移—计划执行—证据记录—恢复”链路上的连接处是否出现新的安全性质或成本矛盾。

## 19. 主线保持与研究边界

本轮精读后，研究中心保持稳定，同时把载体边界适度打开：

> **长期运行 Agent 的持久状态在载体转换和环境变化中的安全演化、能力保留与可恢复性。**

规则和 Skill 仍然是第一阶段的主要载体，记忆、harness／policy、模型升级、工具版本和外部状态可以沿同一条证据链接入。

已有论文用于定义基线、方法组件和保证边界，研究主题可以与它们重叠。形成区分度时，需要明确至少一个新的状态载体、转换操作、威胁模型、保证对象或评价方法：

- 只复现单篇论文的算法和 benchmark，成果边界较窄；
- 将压缩、来源授权、Skill 演化、模型迁移、轨迹证据和恢复连接起来，可以形成跨层研究；
- 只更换模型、数据集或提示词，通常不足以支撑主线贡献；
- 发现已有方法在新状态载体或环境变化下失效，也属于有价值的边界结果。

仍然值得推进的交叉研究是：

1. 长上下文压缩、时间冲突和规则更新后，动作权威是否仍然成立；
2. 记忆派生到 Skill、harness 或 policy 时，哪些来源和限制条件被丢失；
3. Skill 组合和跨会话复用后，污染影响如何沿状态依赖传播；
4. 来源、工具、模型或权限变化后，如何对状态子图做增量重验证；
5. 恢复和模型迁移时如何保留合法能力，并核算长期成本与能力侵蚀；
6. 批准意图、工具参数、外部状态和后续经验如何形成可审计证据链。

这些问题需要以压缩、Skill 演化、记忆授权、迁移评测、轨迹保证和 KV 基础设施方法作为对照。实验结果中要单独标注已有方法提供的组件和保证，本研究把贡献落在状态转换、环境变化、证据闭环和恢复机制的连接处。
